# «Какой картой?» — спецификация MVP

Статус: черновик на согласование. Дата: 2026-11-03.

## 1. Цель

Перед оплатой за несколько секунд понять, какой картой платить, чтобы получить
максимальный кешбэк — с учётом категорий месяца в каждом банке и остатка лимитов.

## 2. Пользователь и контекст

- Один пользователь, один телефон. Основной сценарий — на кассе, одной рукой:
  крупные элементы, поиск на первом экране, работа без сети.
- Банки: основные — Сбер, Т-Банк, ВТБ; редкие — Озон, WB, Яндекс, Альфа.
  Все семь предзаполнены; редкие можно выключить, чтобы не мешали в списке.

## 3. Модель кешбэка

Категорию покупки определяет не магазин, а **MCC-код терминала**. Поэтому
цепочка такая: *магазин → MCC → категория в каждом банке → % с учётом лимита*.

У банка:
- `basePercent` — базовый % на всё, что не попало в категории;
- `rewardType` — `rub` (деньги) или `points` (бонусы: Спасибо, Плюс, Ozon-баллы…);
- `valueCoef` — во сколько рублей оцениваем 1 бонус (0…1). Нужен, чтобы честно
  сравнивать «5 % Спасибо» и «3 % рублями». Предзаполнено ориентировочно:
  рубли — 1.0, Плюс — 0.8, Спасибо — 0.8, Ozon/WB — 0.7. Меняется в настройках;
- `monthlyLimit` — общий лимит кешбэка в месяц (или пусто, если лимита нет).

У категории месяца (своя на каждый банк и месяц):
- название, `percent`, набор MCC (из пресета-группы или вручную), свой лимит (опц.).

Расчёт для покупки с MCC `m` и суммой `amount` (сумма необязательна):

```
pct            = % категории банка, содержащей m, иначе basePercent
rewardRaw      = amount × pct / 100
reward         = min(rewardRaw, остаток лимита категории, остаток лимита банка)
value          = reward × valueCoef            // в «рублёвом эквиваленте»
```

Без суммы сравниваем `pct × valueCoef`; если лимит категории исчерпан —
показываем базовый % и пометку «лимит исчерпан». Банки сортируются по `value`,
при равенстве — по заданному пользователем порядку.

Предзаполненные проценты и лимиты банков — только заготовка; реальные значения
пользователь берёт из приложения банка. Приложение не ходит в банки.

## 4. Экраны

### 4.1 «Где платить» (главный)

- Поле поиска: название магазина или его алиас, 4-значный MCC, название группы.
- Под полем — до 8 кнопок частых магазинов (по истории выбора).
- Результат: банки по убыванию выгоды. Строка: банк · % · «категория X» или
  «базовый» · остаток лимита · ожидаемый кешбэк при введённой сумме.
- Поле суммы (необязательно).
- У строки банка — кнопка «Записать»: покупка попадает в лог, остаток лимита
  уменьшается.
- Если магазин не найден — предложить добавить его с MCC прямо отсюда.
- В новом месяце без заданных категорий — баннер «Скопировать с прошлого месяца?».

### 4.2 «Категории»

- Переключатель месяца (по умолчанию текущий).
- По каждому включённому банку — список категорий: название, %, MCC
  (группа или свой список), лимит.
- Добавить категорию: выбрать группу из пресетов («Супермаркеты», «АЗС»…) или
  ввести MCC вручную; % обязателен.
- Кнопка «Скопировать из прошлого месяца».

### 4.3 «Магазины»

- Поиск, список, добавление и правка: название, алиасы, MCC (с подсказкой
  названия кода), заметка.
- Стартовый набор ~60 популярных сетей с типичными MCC, помечены
  «ориентировочно»: у одной сети MCC может отличаться по точкам, проверять по выписке.

### 4.4 «Банки»

- Включён/выключен, название, цвет, порядок, `basePercent`, `rewardType`,
  название бонусов, `valueCoef`, `monthlyLimit`.

### 4.5 «Ещё»

- Экспорт/импорт JSON — резервная копия и перенос на другой телефон.
- Справочник MCC-групп: просмотр и правка кодов.
- Лог покупок за месяц, удаление записи.

## 5. Данные

Хранение: `localStorage`, один JSON-документ, `schemaVersion` для миграций.

```js
{
  schemaVersion: 1,
  banks: [{ id, name, color, order, enabled,
            basePercent, rewardType: 'rub'|'points', pointsName,
            valueCoef, monthlyLimit }],
  mccGroups: [{ id, name, codes: [5411, 5499] }],
  stores: [{ id, name, aliases: [], mcc, note, usedCount, lastUsedAt }],
  plans: [{ month: '2026-11', bankId,
            categories: [{ id, name, percent, codes: [], limit }] }],
  purchases: [{ id, date, bankId, categoryId, mcc, amount, reward }]
}
```

Остатки лимитов не хранятся — считаются из `purchases` за месяц.

## 6. Технологии

- Статический PWA: HTML + CSS + JS (ES-модули). Без сборки и без зависимостей —
  открывается с любого хостинга, правится любым редактором.
- `manifest.webmanifest` + service worker: установка на главный экран, работа офлайн.
- Логика — в чистых модулях `src/core/` (поиск, ранжирование, лимиты, месяцы,
  схема/миграции); UI — тонкий слой `src/ui/`.
- Тесты ядра: `node --test tests/`, без фреймворков.
- Хостинг: GitHub Pages (PWA требует HTTPS). Альтернатива — свой сервер.
  Личные данные (категории, покупки) на хостинг не попадают — только в браузере.
- Код и комментарии — на английском, интерфейс — на русском.

Структура:

```
index.html  styles.css  manifest.webmanifest  sw.js
src/app.js            # загрузка состояния, навигация по экранам
src/ui/*.js           # по модулю на экран
src/core/{match,rank,limits,months,state}.js
src/data/{banks,mcc-groups,stores}.js   # предзаполнение
tests/*.test.js
```

## 7. Не входит в MVP

- Распознавание категорий по скриншоту приложения банка.
- Импорт выписок: автоопределение MCC магазинов и автоучёт лимитов.
- Подсказка, какие категории выбрать на месяц, по истории трат.
- Telegram-бот.
- Синхронизация между устройствами (пока — экспорт/импорт).

## 8. Критерии приёмки

1. На телефоне приложение добавляется на главный экран и открывается без сети.
2. Ввод «пятёрочка» даёт список банков с % и остатком лимитов.
3. Ввод суммы показывает кешбэк в рублёвом эквиваленте по каждому банку
   с учётом лимитов.
4. Категории на месяц задаются из пресетов; копирование из прошлого месяца работает.
5. «Записать» уменьшает остаток лимита; в новом месяце остатки полные.
6. Экспорт → импорт на другом устройстве восстанавливает всё без потерь.
7. Тесты ядра зелёные: матчинг (магазин / MCC / группа, ё/е, регистр),
   ранжирование с коэффициентом, лимиты категории и банка, смена месяца,
   миграция схемы.

## 9. Открытые вопросы

1. Хостинг: GitHub Pages в публичном репозитории или свой сервер?
2. Учёт покупок для лимитов — нужен в MVP, или достаточно показывать лимиты
   справочно и обойтись без кнопки «Записать»?
3. Коэффициенты ценности бонусов по умолчанию (п. 3) — устраивают?
